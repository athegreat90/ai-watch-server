# AI Watch server

A small Python server (standard library only) that collects the status of your AI coding agents and serves it to the AI Watch. Sessions and usage limits are kept in memory.

```
agents -> hooks --POST /api/events--> server <--GET /api/status-- watch
```

Related repositories: [hooks](https://github.com/athegreat90/ai-watch-hooks) | [firmware](https://github.com/athegreat90/ai-watch-firmware). This is server v1.1.0; use the 1.1.0 release of the hooks and firmware.

## Requirements

- Docker with Compose, `git` and Python 3 (Python only creates the token and runs the health check).
- A host on a private network you trust. The server has no TLS.

## Quick start (published image)

Clone this repository and run commands from its root. Start the server before configuring the hooks or the watch.

PowerShell:

```powershell
git clone https://github.com/athegreat90/ai-watch-server.git
cd ai-watch-server
python bridge/init_config.py
Copy-Item .env.example .env
```

Zsh or Bash:

```sh
git clone https://github.com/athegreat90/ai-watch-server.git
cd ai-watch-server
python3 bridge/init_config.py
cp .env.example .env
```

Then configure (see the table below) and start:

```sh
docker compose -f compose.release.yaml pull
docker compose -f compose.release.yaml up -d --wait
docker compose -f compose.release.yaml ps
docker compose -f compose.release.yaml logs --tail 100
python bridge/check_api.py     # python3 on Zsh or Bash
```

`check_api.py` verifies health, rejection of anonymous requests, and authenticated reads.

## Configuration

| Where | Setting | Meaning |
|---|---|---|
| `.env` | `MONITOR_HOST_BIND` | The Docker host's private LAN IPv4, for example `192.168.1.50`. Default is loopback. Never `0.0.0.0` on a host with a public interface. |
| `.env` | `AI_WATCH_SERVER_IMAGE` | Release tag to install |
| `bridge/config.local.json` | `url` | Same origin as the bind address, for example `http://192.168.1.50:8765` |
| `bridge/config.local.json` | `token` | Generated by `init_config.py` (at least 24 characters). Share it only with your hooks and watch configuration. |
| `bridge/config.local.json` | `port` | Optional, default `8765` |

`bridge/config.example.json` is the template, `config.local.json` is your ignored copy. Without Docker the bind address comes from the `MONITOR_BIND` environment variable. The [Linux guide](docs/DEPLOY-LINUX.md) lists the remaining `.env` variables (`MONITOR_HOST_PORT`, `PUID`, `PGID`).

## Usage

GET `/health` is public. `/api/status`, `/api/sessions` and the POST endpoints require the `X-Monitor-Key` header. Hooks post events to `/api/events`; usage limits go to `/api/limits` and come back in `/api/status`. Fields, errors and limits are in the [API reference](docs/API.md).

To upgrade or roll back, change the tag in `.env` and repeat the pull and up commands. Keep the same host address and token. Sessions are in memory and clear on restart.

## Security model

- Plain HTTP and a shared token: expose the server only to a trusted LAN, firewall the port and do not forward it on your router.
- Keep `bridge/config.local.json` out of version control (it is ignored) and never post the token in issues.
- Request bodies are limited to 4096 bytes and concurrent connections to 16.

## Troubleshooting

- HTTP 401: the token differs from the one in the hooks or the watch.
- Cannot reach the server from another machine: check `MONITOR_HOST_BIND`, the firewall and the subnet. On Docker Desktop (Windows or macOS) allow the port in the host firewall.
- Container restarts on a permission error: set `PUID` and `PGID` in `.env` to the owner of `config.local.json`.
- More cases, with systemd and firewall steps, in the [Linux guide](docs/DEPLOY-LINUX.md).

## Build from source

Run `./scripts/deploy-server.ps1` in PowerShell or `zsh scripts/deploy-server.zsh` in Zsh. Use the matching `status` script for a local build.
