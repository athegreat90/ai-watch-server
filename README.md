# AI Watch server

A small, static Go server that collects the status of your AI coding agents and serves it to the AI Watch. Sessions and usage limits are kept in memory. It runs from a ~27 MB distroless container image (`linux/amd64`, `linux/arm64`) with no Python, shell or source build on the target machine.

```
agents -> hooks --POST /api/events--> server <--GET /api/status-- watch
```

Related repositories: [hooks](https://github.com/athegreat90/ai-watch-hooks) | [firmware](https://github.com/athegreat90/ai-watch-firmware). The HTTP API is unchanged from the Python server of v1.1.0, so existing hooks and firmware keep working.

## Quick start (Docker only)

1. Download `ai-watch-deploy-vX.Y.Z.zip` from the [latest release](https://github.com/athegreat90/ai-watch-server/releases) and unzip it.
2. Run the installer in that folder.

```sh
./install.sh            # Linux, macOS, Raspberry Pi, WSL
```

```powershell
.\install.ps1           # Windows Docker Desktop (PowerShell 5.1 or 7)
```

3. The installer creates the token, starts the container, waits for health, runs the API check and prints the deployed version and digest.

Requirements: Docker with Compose, and a private network you trust (the server has no TLS). Details, `docker run` and Compose methods, updates and rollback: [deploy/ai-watch-deploy/README.md](deploy/ai-watch-deploy/README.md) and the [Linux guide](docs/DEPLOY-LINUX.md).

## `latest` or a pinned version

| Image tag | Behavior | Use it for |
|---|---|---|
| `ghcr.io/athegreat90/ai-watch-server:latest` | Newest stable release. A mutable tag. | Tracking releases |
| `ghcr.io/athegreat90/ai-watch-server:vX.Y.Z` | One immutable release. | Reproducible installs, rollback |

`latest` does **not** update a running container: pull and recreate it (`./install.sh --update`). Roll back by choosing an earlier version (`./install.sh --rollback v1.1.0`). Both tags of a release share one multi-platform image digest; prereleases never move `latest`. To check, compare `docker buildx imagetools inspect <image>:latest --format '{{json .Manifest}}'` with the versioned tag.

## Configuration

| Where | Setting | Meaning |
|---|---|---|
| `.env` | `AI_WATCH_SERVER_IMAGE` | `...:latest` or `...:vX.Y.Z` |
| `.env` | `MONITOR_HOST_BIND` | Host address to listen on. Default `127.0.0.1`; use the host's private LAN IPv4 for the watch and hooks. Never `0.0.0.0` on a host with a public interface. |
| `.env` | `MONITOR_HOST_PORT`, `PUID`, `PGID` | Host port (default `8765`); the user that owns `config.local.json` |
| `config.local.json` | `token` | Generated by `ai-watch-server init-config` (256-bit, mode 0600). At least 24 characters. Share it only with your hooks and watch. |
| `config.local.json` | `url`, `port` | Origin used by the hooks and checker; optional listen port (default `8765`) |

Server environment: `AI_WATCH_CONFIG` (config path), `MONITOR_BIND` (listen address), `MONITOR_READ_TIMEOUT` / `MONITOR_WRITE_TIMEOUT` (Go durations, default `3s`).

## Usage

GET `/health` is public. `/api/status`, `/api/sessions` and the POST endpoints require the `X-Monitor-Key` header. Hooks post events to `/api/events`; usage limits go to `/api/limits` and come back in `/api/status`. Fields, errors and limits: [API reference](docs/API.md). Sessions are in memory and clear on restart.

Verify any server from any machine with the standalone, read-only checker (release asset, no Python or Go needed):

```sh
ai-watch-check-api --url http://192.168.1.50:8765 --token-file ./config.local.json
```

It checks health, rejection of anonymous and wrong tokens, and the authenticated responses. Token via `--token-file` or `AI_WATCH_TOKEN`, never an argument. Exit codes: 0 ok, 1 check failed, 2 usage, 3 unreachable; `--json` for automation.

## Security model

- Plain HTTP and a shared token: expose the server only to a trusted LAN, firewall the port and do not forward it on your router.
- Keep `config.local.json` out of version control and never post the token in issues.
- Container: non-root, read-only root filesystem, all capabilities dropped, `no-new-privileges`, 0.5 CPU / 128 MB / 64 processes.
- Request bodies are limited to 4096 bytes and concurrent connections to 16.

## Troubleshooting

- HTTP 401: the token differs from the one in the hooks or the watch.
- Cannot reach the server from another machine: check `MONITOR_HOST_BIND`, the firewall and the subnet. On Docker Desktop allow the port in the host firewall.
- Container restarts with `cannot read config.local.json`: set `PUID` and `PGID` in `.env` to the owner of the file.
- More cases in the [Linux guide](docs/DEPLOY-LINUX.md).

## Development

```sh
go test -race ./...                 # -race needs a C compiler; or run it inside a golang container
go build ./cmd/ai-watch-server ./cmd/ai-watch-check-api
bash bench/parity.sh                # same request suite against the Go server and the Python reference
```

The original Python server (`bridge/server.py`) is kept only as the compatibility reference for parity tests and benchmarks (`bench/`). Build the container from a checkout with `zsh scripts/deploy-server.zsh` or `./scripts/deploy-server.ps1`.
